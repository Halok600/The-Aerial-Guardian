Pipeline

Four stages, one forward pass

No SAHI slicing, no multi-pass tiling — a single high-resolution forward pass through a 4-scale detection head handles targets as small as 8px.

01

Detect — YOLOv8n-P2

A stride-4 detection head is grafted onto YOLOv8n's backbone, on top of the standard P3/P4/P5 heads — giving a 320×180 grid at imgsz 1280 for catching 8–16px pedestrians that standard YOLOv8 misses.

2.9M params
02

Stabilise — ECC CMC

OpenCV's ECC algorithm estimates inter-frame drone ego-motion on a downscaled 320×180 grayscale frame, producing an affine warp used to correct Kalman-predicted positions.

Python only
03

Track — ByteTrack

A 3-stage Hungarian association (high-conf → low-conf → lost-track re-activation) over IoU cost, backed by an 8D constant-velocity Kalman filter per track.

Runs in-browser
04

Render — Trails & HUD

Golden-angle hue spacing gives every track ID a visually distinct, stable color; a single blended overlay draws fading trajectory tails without per-segment cost blow-up.

⚠ Model quality is a work in progress

This detector is trained on a genuinely small dataset (under 2,000 frames from 6 VisDrone sequences) for aerial targets as small as 8–16px — one of the hardest regimes in object detection. Expect missed detections, especially at low confidence.

  • Training is actively continuing on the original RTX 3050 — later checkpoints will be re-exported here.
  • Lower the confidence slider if nothing is detected; raise it if you see false positives.
  • The biggest lever for improvement is more training data — the full VisDrone-MOT training split (56 sequences) instead of just its validation split.
  • Camera-motion compensation (ECC) is not ported to the browser; expect more ID switches on fast-panning footage than the Python demo clips above.

Built with YOLOv8, ONNX Runtime Web, and a from-scratch ByteTrack implementation. Source on GitHub — 100% free, static, client-side hosting.
